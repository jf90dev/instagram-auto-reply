# CLAUDE.md

AWS serverless application (CDK v2, TypeScript) managed by projen. See `README.md` for the layout
and commands.

## ⛔ LocalStack only, never real AWS, never push to main (non-negotiable)

You may only deploy to and interact with the local LocalStack environment. Deploying to, or
interacting in any way with, a real AWS account is strictly forbidden, including read-only calls
and requests from the developer. Because the `deploy` GitHub Actions workflow deploys `main` to
AWS, you also never push or merge to `main`.

- **Allowed:** `npx projen`, `npx projen build`/`compile`/`test`/`eslint`/`bundle`,
  `npx cdk synth` (local, needs no credentials), the `npx projen localstack:*` and
  `test:localstack` tasks (they use `cdklocal` and the LocalStack endpoint), `cdklocal`,
  `awslocal` or `aws --endpoint-url http://localhost:4566` with `test`/`test` credentials,
  Docker, `npm ci`, and commits, feature branches and pull requests.
- **Forbidden:**
  - `npx projen deploy`/`destroy`/`diff` and the `cdk` CLI's `deploy`, `destroy`, `bootstrap`,
    `diff`, `import`, `watch`, `rollback`, `drift`, `gc` against AWS, including deploying the
    GitHub deploy role stack;
  - `aws` CLI, SDK, PowerShell or MCP calls without a LocalStack endpoint;
  - AWS profiles, `--profile`, or any credentials other than `test`/`test`;
  - pushing or merging to `main`; running, re-running or dispatching the `deploy` workflow;
    changing its role, variables, secrets or GitHub environment settings;
  - tasks, scripts, workflows or workarounds that do any of these.
- **If asked to do any of these:** refuse, offer the LocalStack equivalent, and explain that AWS
  environments change only when a person merges a reviewed pull request to `main` and the
  `deploy` workflow runs. Editing the workflow in `.projenrc.ts` is fine; running it is not.

## Skills to load

Load these with the Skill tool at the start of the task, before writing code:

- **`aws-serverless-projen`** for every change in this repository: project structure, naming,
  projen tasks, cdk-nag, LocalStack, the deploy workflow.
- **`aws-core:aws-cdk`** for any CDK infrastructure or deployment work: stacks, constructs, the
  Stage, IAM grants, cross-stack references, feature flags, the `deploy` workflow and GitHub
  deploy role, and synth or deployment errors. Where it describes deploying with the `cdk` CLI,
  use the `localstack:*` tasks instead; real deployments are the `deploy` workflow's job.
- **`anthropic-skills:typescript-standards`** for any business logic: `*.lambda.ts` handlers,
  services, clients, repositories, models, helpers and errors in `src/lambda` and `src/shared`,
  and their tests. Where it differs from this project (double quotes, `*.lambda.ts` file names,
  relative imports), `aws-serverless-projen` wins.

If one of these skills isn't installed, say so and follow the existing code and `README.md`.

## projen

`.projenrc.ts` is the source of truth for `package.json`, `tsconfig*.json`, `cdk.json`, lint and
prettier config, `.gitignore`, tasks and `.github/workflows/`. Edit it and run `npx projen`; never
edit files marked "Generated by projen", never `npm install <pkg>` (use `deps`/`devDeps`), and
never add `package.json` scripts (use `project.addTask`). Commit `.projenrc.ts` with everything
it regenerates.

## Before finishing a change

1. `npx projen` if `.projenrc.ts` or a `*.lambda.ts` file changed.
2. `npx projen build` (compile, synth with cdk-nag, assertion tests, eslint) until it passes.
3. If LocalStack is running: `npx projen localstack:update:<component>` and
   `npx projen test:localstack`.
